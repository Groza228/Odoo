# Бібліотека

## Структура та звʼязки

Модуль використовує окремі записи `library.member`, а не `_inherits` від
`res.partner`. Читацький квиток не залежить від модуля контактів, тому єдина
залежність модуля — `base`. Для читачів передбачено обовʼязковий унікальний
`membership_number`.

`library.book` — бібліографічний запис із полем `copy_ids` One2many для
фізичних примірників `library.copy`. Кожен примірник має обовʼязкове поле
`book_id` Many2one з `ondelete='restrict'`: видалення книги не повинно
мовчки видаляти її фізичні примірники. Видача має обовʼязкові поля `copy_id`
і `member_id` Many2one, також із `ondelete='restrict'`, щоб зберігати історію
видач, коли примірник або читач уже використовувався.

У формі видачі відображаються повʼязані дані книги та читача. Примірник
вважається вільним, якщо для нього не існує видачі зі станом `active`.

## Згенеровано AI та виправлено вручну

Початкові модель книги, її представлення, меню та мінімальна залежність
`base` були згенеровані без структурних змін. Під час ревʼю вручну додано
моделі примірника, читача та видачі, правила доступу, представлення й демо-
дані.

Поведінку видалення звʼязків обрано вручну: усі обовʼязкові Many2one-поля
використовують `ondelete='restrict'`, а не небезпечний каскад, щоб зберегти
фізичні примірники та історію видач. Також вручну перевірено обовʼязковість
полів книги, примірника, видачі й читача. Обмеження унікальності читачів
реалізовано через API `models.Constraint` в Odoo 19.

## Практика ORM shell

Запуск shell із кореня репозиторію:

```powershell
python odoo-bin shell -c odoo.conf -d Test
```

Наведені запити виконано в базі `Test` 26.10.2026.

```python
env['library.book'].search([('author', '=', 'Роберт К. Мартін')])
```

Результат: `['Чистий код']`.

```python
book = env['library.book'].search([('author', '=', 'Роберт К. Мартін')], limit=1)
free = book.copy_ids.filtered(
    lambda copy: not env['library.loan'].search_count([
        ('copy_id', '=', copy.id),
        ('state', '=', 'active'),
    ])
)
len(free)
```

Результат: `1` вільний примірник книги «Чистий код».

```python
env['library.loan'].search([
    ('state', '=', 'active'),
    ('due_date', '<', fields.Date.today()),
])
```

Результат: одна прострочена активна видача — видача книги «Чистий код»
читачці Анні Коваленко.

```python
loan = env['library.loan'].create({
    'copy_id': env['library.copy'].search([], limit=1).id,
    'member_id': env['library.member'].search([], limit=1).id,
    'due_date': fields.Date.today(),
})
loan.write({'state': 'returned', 'return_date': fields.Date.today()})
```

Результат: нову видачу створено зі станом `active`, а потім змінено на
`returned` із поточною датою повернення.

## Як перевірити етап Прострочено

1. **Через демо-дані.** Оновіть модуль у базі `Test`:

   ```powershell
   python odoo-bin -d Test -u library_rental --stop-after-init
   ```

   Демо-видачі зі старими датами завантажуються в `install_mode`. Після
   оновлення відкрийте меню «Видачі» й перевірте етап «Прострочено».

2. **Через Odoo shell.** Для тестової старої дати використовуйте контекст,
   який не діє для звичайних користувачів:

   ```python
   from datetime import timedelta
   from odoo import fields

   loan = env['library.loan'].with_context(
       allow_past_loan_date=True,
   ).create({
       'copy_id': env['library.copy'].search([], limit=1).id,
       'member_id': env['library.member'].search([], limit=1).id,
       'loan_date': fields.Date.context_today(env['library.loan']) - timedelta(days=20),
   })
   loan.display_state
   ```

   Результат: `overdue`. Після тесту видаліть створену видачу.

3. **У Python-тесті.** Створіть тестову видачу з
   `allow_past_loan_date=True` і перевірте
   `loan.display_state == 'overdue'`, `loan.days_late` та
   `loan.current_fine`. Не використовуйте цей контекст у звичайному
   користувацькому сценарії: минула дата відхиляється, а після створення
   `loan_date` змінювати не можна.

## Групи та права доступу

Модуль має дві незалежні групи в категорії «Бібліотека»:

- **Бібліотекар** — повне керування книгами, примірниками, читачами та
  видачами.
- **Читач** — перегляд книг, примірників і власних видач. Пункт «Мої
  видачі» використовує правило доступу, тому читач не бачить чужі видачі.

Бібліотекар не включає Читача через `implied_ids`. Це навмисно: інакше
правило для Читача могло б обмежити бібліотекарю перегляд усіх видач.

| Модель | Бібліотекар | Читач |
|---|---|---|
| `library.book` | читання, зміна, створення, видалення | лише читання |
| `library.copy` | читання, зміна, створення, видалення | лише читання |
| `library.member` | читання, зміна, створення, видалення | немає доступу |
| `library.loan` | читання, зміна, створення, видалення | лише читання власних видач |

Для `library.loan` діє record rule з доменом
`[('member_id.user_id', '=', user.id)]`. Групу правила задано явно, а не
залишено порожньою, щоб правило не стало глобальним і не заблокувало
бібліотекаря або адміністратора. Кнопки «Повернути» та «Відновити» у формі
додатково приховані для Читача.

Поле `library.member.user_id` є необовʼязковим Many2one до `res.users` з
`ondelete='set null'`. Обмеження `UNIQUE(user_id)` забороняє привʼязати одного
користувача до кількох читачів, але дозволяє кільком читачам залишатися без
облікового запису (`NULL`).

### Перевірка під Читачем

У shell перевірте demo-користувача або створіть тимчасового користувача з
`group_ids` (у Odoo 19 це поле називається саме `group_ids`):

```python
reader = env.ref('library_rental.user_reader_demo')
reader_loans = env['library.loan'].with_user(reader).search([])
assert all(loan.member_id.user_id == reader for loan in reader_loans)
assert env['library.book'].with_user(reader).search([])
```

Читання чужої видачі, доступ до `library.member`, а також створення, зміна
чи видалення книг і видач мають завершуватися `AccessError`. Для порівняння
`library.loan.with_user(librarian).search([])` і той самий запит від
адміністратора мають повертати всі доступні видачі.

## Wizard повернення

Кнопка «Оформити повернення» доступна бібліотекарю у формі активної
видачі. Wizard містить видачу `loan_id`, стан примірника після повернення
`condition_on_return` і необовʼязкову примітку `notes`. Варіанти стану
примірника беруться без дублювання з поля `library.copy.condition`, а
`default_get` підставляє активну видачу та її поточний стан.

Підтвердження спочатку викликає штатний `action_return()`, а потім записує
`return_note` у видачу та новий стан примірника. Примітка доступна лише для
читання у формі видачі й показується тільки коли заповнена. Дія «Повернути»
залишена як швидке повернення без зміни стану примірника.

## Звіт «Історія видач читача»

Звіт друкується з форми читача через меню дій. Він формує окрему сторінку
для кожного читача, показує книги, дати, етапи, штрафи та примітки при
поверненні, а внизу підсумовує кількість видач і суму штрафів. Для читача
без видач виводиться «Видач немає». Звіт доступний лише групі
«Бібліотекар»; читач не має доступу до `library.member` і не може його
надрукувати.
